# 📖 aiohttp 核心心法实战 Demo (逐行精讲版)

这份文档基于我们在实战中对 `src/aiohttp_core_demo.py` 的探讨，提取了每一行代码背后深藏的架构思维与底层原理，作为复盘笔记。

## 1. 职业程序员的素养：日志系统 (Line 16-17)

```python
logging.basicConfig(level=logging.INFO, format='%(asctime)s - %(message)s')
logger = logging.getLogger(__name__)
```

*   **`%(asctime)s` 为什么带毫秒？**
    Python 底层默认采用 `YYYY-MM-DD HH:MM:SS,mmm` 格式，`,` 后的三位数表示精准到千分之一秒的毫秒。在高并发中追踪网络耗时，毫秒级的颗粒度绝对不能少。
*   **什么是 `__name__`？**
    这是 Python 的内置魔术变量。当文件直接被运行时，它的值强制为 `"__main__"`（认定为主程序）；当被导入时，显示真实模块名（如 `"src.aiohttp_core_demo"`）。
*   **明明 `format` 里没写 `%(name)s`，为什么要写 `getLogger(__name__)`？**
    这是高级开发者的**防御性编程（代码洁癖）**。这是为了给代码打上防干涉的“出厂铭牌”。以后把它合并到大系统时，只要大系统开启全局配置，这行代码发出的日志就绝对不会和别人混淆，也不会污染全局 Root 节点。

## 2. 全局总控阀门与打靶神器 (Line 20-27)

```python
CONCURRENCY_LIMIT = 50   
CONNECTION_LIMIT = 50    
TOTAL_REQUESTS = 200     
TARGET_URL = "https://httpbin.org/delay/2"
```

*   **这是常量对吗？**
    是的。虽然 Python 在执行中可以修改它，但全行业达成的硬核契约（PEP 8）规定：**全大写字母加下划线**即为全局常量。想动系统总闸，直接在这里改，绝不深入函数内部寻觅。
*   **`httpbin.org/delay/2` 是怎么运作的？**
    这是给全网开发者的高并发“靶弹测试API”。对它发请求，它会在服务器强制 Sleep 整整 2 秒，然后把你发出的信息原装退回。这极好地模拟了高并发下，服务器处理极其缓慢导致请求拥挤在本地发包河道的“连环超时”灾难场景。

## 3. 架构师的“依赖注入”思维 (Line 29-33)

```python
async def fetch_data(session: aiohttp.ClientSession, url: str, sem: asyncio.Semaphore, task_id: int):
    """
    一股准备冲击大坝下泄的水流（执行单个网络请求的具体协程）
    """
```

*   **在定义函数时，我怎么知道该传哪些参数？（依赖注入）**
    只需在大脑里过一遍“这滴水出海”必经的流程：
    1. 拿什么工具出海？ -> 需要大本营统一派发的提货车队 `session`。
    2. 去哪里提货？ -> 目标地址 `url`。
    3. 受什么全局约束？ -> 必须由大坝总指挥部的闸门 `sem` 控制，而不是工人偷偷自己造个闸。
    4. 如果报错了拿什么认尸？ -> 需要赋予身份铭牌 `task_id` 以便打日志追踪。
*   **为什么要纠正“工人”的比喻？**
    为了保持架构层面的**绝对逻辑自洽**。外面是 `Semaphore(水库大坝)`，底下是 `TCPConnector(物理河道)`，那在这里进入并发环节的就不该是“工人”，而是必须对齐为“一滴准备出海的水流”。

## 4. 并发洋葱模型与性能打点 (Line 35-42)

```python
    async with sem:
        logger.info(f"任务 [{task_id:03d}] 🚦 被大坝放行...")
        start_time = time.time()
        
        try:
            async with session.get(url) as response:
```

*   **代码套娃太多了，我怎么知道该怎么组织这套结构？**
    处理高并发永远记住三步走的黄金法则（洋葱模型）：“**先领号排队 -> 再买保险 -> 最后扬帆出海**”。
    1. **排队 (`async with sem`)**：最外面套的绝对是并发锁，没拿到通行证绝对不准触发耗时倒计时。
    2. **买保险 (`try...except`)**：只要准备干活，随时可能遇到惊涛骇浪（断网、宕机），必须先铺好错误拦截网。
    3. **出海 (`async with session.get`)**：在兜底保护下，放心去远方抓数据。
*   **`task_id:03d` 是什么魔法？**
    `d` 即整数，`3` 为字符宽度，`0` 为补零占位（比如 `1` 会被打印为 `001`）。这是高级审美：确保终端打印的千百条并发日志像 Excel 表格一样**绝对垂直对齐**，专治查 Bug 瞎眼。
*   **`time.time()` 是什么，为什么要放这里？**
    获取距离标准纪元时间以来的绝对秒数。在这里它充当了**“秒表起始键”**的角色。在请求回来后，用 `现有时间 - 刚才时间`，就能得出这起单发请求消耗的极高精度毫秒数。这在工业架构里叫做**性能耗时打点（Profiling）**，专门用来揪出“跑得通但跑得慢”的业务毒瘤。
