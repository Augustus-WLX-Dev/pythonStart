# 用片场故事讲懂 Python Asyncio

> 面向第一次接触 `asyncio` 的读者。
>
> 这篇文章先不死磕源码，而是用“电影片场”的画面，帮你理解 `Event Loop`、`Ready Queue`、`Task`、`Coroutine`、`Future` 和 `await` 之间的关系。

推荐继续阅读：[Event loop 剖析](event_loop.md)

---

## 先记住一句话

`asyncio` 不是让很多段 Python 代码真正同时运行。

它更像一个电影片场：

> **主摄像机同一时间只能拍一个演员。**
>
> 演员如果要等道具、等场景、等饭做好，就主动离开镜头。
>
> 导演趁这段时间去拍别人。
>
> 等演员准备好了，再回到候场区，接着刚才的位置继续演。

这个“主摄像机 / 总导演”，就是 **Event Loop**。

这个“候场区”，就是 **Ready Queue**。

---

## 一、角色对照表

先把几个核心概念放到同一个片场里：

| asyncio 概念 | 片场比喻 | 你可以先这样理解 |
| --- | --- | --- |
| `Coroutine` | 剧本 | `async def` 写出来的剧情，只描述动作，自己不会执行 |
| `Task` | 拿着剧本的演员 | 真正推动 coroutine 一步步往下走 |
| `Event Loop` | 总导演 / 主摄像机 | 不断决定下一个该让谁获得 CPU 控制权 |
| `Ready Queue` | 候场区 | 已经准备好继续执行的任务，在这里排队等叫号 |
| `await` | 主动让出镜头 | 当前任务暂时演不下去了，把控制权还给 Event Loop |
| `Future` | 幕后通知单 | 等待某件事完成；完成后通知 Task 回来候场 |
| `ThreadPool` | 幕后工作间 | 专门处理会卡住主摄像机的阻塞工作 |

---

## 二、Event Loop：片场里的总导演兼主摄像机

`asyncio` 里的 Event Loop，可以理解成片场里的总导演。

它手里拿着一份候场名单，不断问：

> 下一个谁准备好了？谁可以上来拍？

这份候场名单，就是 **Ready Queue**。

Event Loop 每次都会从 Ready Queue 里叫一个任务出来，让它获得一小段 CPU 时间。

注意，是“一小段”，不是从头演到尾。

因为在 `asyncio` 的世界里，任务都很懂规矩：

> 如果自己暂时没法继续，就通过 `await` 主动把镜头让出来。

---

## 三、Coroutine：程序员写好的剧本

当你写下：

```python
async def cook():
    print("开始做饭")
    await asyncio.sleep(3)
    print("饭做好了")
```

这个 `cook()` 就像一段剧本。

它写明了剧情：

1. 先说：“开始做饭”
2. 等饭做好
3. 再说：“饭做好了”

但是，剧本自己不会跑到镜头前表演。

也就是说：

> **Coroutine 是剧本，不是演员。**
>
> 它描述要做什么，但自己不会主动执行。

### 做饭这个例子，应该怎么想？

这里的 `await asyncio.sleep(3)` 不要理解成演员真的站在镜头前发呆 3 秒。

它更像电影里的剪辑：

> 演员演完“我把饭放进锅里了”，导演不会让摄像机一直拍着锅和演员干等。
>
> 镜头会立刻切到另一个场景，去拍另一个演员。
>
> 等剧情里的饭做好了，镜头再切回来，让这个演员接着演“饭做好了”。

所以，`await` 不是让整个片场停住，而是让当前演员先退场等待。

---

## 四、Task：真正拿着剧本上场的演员

当 `asyncio` 要真正运行一个 coroutine 时，会把它包装成一个 **Task**。

Task 就像演员。

它拿着剧本，站到片场里，等待 Event Loop 叫号。

比如：

```python
task = asyncio.create_task(cook())
```

这句话可以想象成：

> 给 `cook()` 这段剧本安排一个演员，让他进入候场区。

从这一刻开始，`cook()` 不再只是剧本，它有了一个真正负责表演的人：`Task`。

---

## 五、asyncio.run(main())：片场正式开机

当你写：

```python
asyncio.run(main())
```

就像制片厂宣布：

> 开机！

这时大致会发生几件事：

1. Python 搭好一个片场，也就是创建 Event Loop。
2. `main()` 这段剧本被拿出来。
3. Event Loop 把它包装成主 Task。
4. 主 Task 进入 Ready Queue 候场。
5. Event Loop 开始叫号拍摄。

简单说：

> `asyncio.run(main())` 就是启动片场，让 Event Loop 开始调度所有演员。

---

## 六、Ready Queue：演员候场区

Ready Queue 是理解 Event Loop 的关键。

你可以把它想象成片场门口的一排椅子：

> 所有已经准备好继续表演的演员，都坐在这里等导演叫。

Event Loop 每次做的事情很简单：

1. 从 Ready Queue 里叫一个演员出来。
2. 给他一点镜头时间。
3. 让他按照剧本往下演。
4. 如果他遇到 `await`，就暂停他，换下一个演员。

所以，Ready Queue 不是“所有任务的仓库”。

更准确地说：

> **Ready Queue 放的是已经准备好马上继续执行的任务。**

那些正在等待 IO、定时器、线程结果的任务，还不能回到候场区。

---

## 七、await：演员说“我先去等一下，你拍别人吧”

比如：

```python
await asyncio.sleep(3)
```

这句代码非常重要。

它不是说：

> 整个片场停 3 秒。

而是说：

> 我这个演员要等 3 秒。导演，你先拍别人吧。

如果一个演员正在演做饭剧情，演到一半发现：

> 米饭还要再煮 3 分钟。

他不会站在主摄像机前干等 3 分钟。

在电影里，这 3 分钟通常会被剪掉，或者镜头会切到别的角色身上：有人在洗菜，有人在烧水，有人在准备餐具。

在 `asyncio` 里也一样。

当前 Task 遇到 `await` 后，会主动暂停，并把 CPU 控制权交还给 Event Loop。

Event Loop 收回镜头，转身去 Ready Queue 里叫下一个已经准备好的 Task。

所以：

> **`await` 的本质，是当前任务主动让出 CPU 控制权。**

---

## 八、为什么 asyncio 能同时处理很多事？

因为它不是让一个演员从头演到尾。

它更像现代电影拍摄：电影最终播放时有固定顺序，但真实拍摄时，导演会根据谁准备好了、哪个场地空了、哪个镜头能拍了，灵活安排。

比如你有三个任务：

```python
async def make_coffee():
    print("开始煮咖啡")
    await asyncio.sleep(3)
    print("咖啡好了")


async def toast_bread():
    print("开始烤面包")
    await asyncio.sleep(2)
    print("面包好了")


async def boil_egg():
    print("开始煮鸡蛋")
    await asyncio.sleep(5)
    print("鸡蛋好了")
```

如果用普通同步方式，可能是：

> 煮咖啡等 3 秒，烤面包等 2 秒，煮鸡蛋等 5 秒，总共 10 秒。

但用 `asyncio`，片场调度会更像这样：

| 时间点 | 片场发生了什么 |
| --- | --- |
| 0 秒 | 咖啡演员上场，说“开始煮咖啡”，然后退场等 3 秒 |
| 0 秒 | 面包演员上场，说“开始烤面包”，然后退场等 2 秒 |
| 0 秒 | 鸡蛋演员上场，说“开始煮鸡蛋”，然后退场等 5 秒 |
| 2 秒 | 面包好了，面包演员回到 Ready Queue，等待导演叫号 |
| 3 秒 | 咖啡好了，咖啡演员回到 Ready Queue，等待导演叫号 |
| 5 秒 | 鸡蛋好了，鸡蛋演员回到 Ready Queue，等待导演叫号 |

这就是异步并发。

> 不是三个人同时占用主摄像机。
>
> 而是他们在等待时都不霸占镜头，所以导演可以继续拍别人。

---

## 九、Future：幕后场务的通知单

那 Event Loop 怎么知道哪个演员等完了呢？

这就需要 **Future**。

Future 可以想象成幕后场务手里的一张通知单。

比如面包演员说：

> 我要等烤箱 2 秒。

于是幕后场务拿着一张通知单：

> 面包好了以后，通知面包演员回来候场。

2 秒后，烤箱完成。

Future 就像场务按下对讲机：

> 面包演员可以回来了！

于是这个 Task 被重新放回 Ready Queue。

注意，它不是马上执行。

它只是回到了候场区。至于什么时候继续演，还要看 Event Loop 什么时候叫到它。

---

## 十、Task 是怎么“接着上次的地方”继续演的？

这是 `await` 很神奇的地方。

当一个 Task 在 `await` 处暂停时，它会记住自己演到哪里了。

就像演员在剧本上夹了一个书签：

> 我刚才演到“等待面包烤好”这里，等回来以后从这里继续。

所以当 Future 通知它可以继续时，Task 不会从头开始运行。

它会从上次暂停的 `await` 后面继续。

比如：

```python
print("开始烤面包")
await asyncio.sleep(2)
print("面包好了")
```

第一次执行时：

```python
print("开始烤面包")
```

然后在 `await` 这里暂停。

2 秒后恢复时，直接继续：

```python
print("面包好了")
```

这就像演员换完衣服、等完道具、场景准备好以后，回到片场继续演下一句台词。

---

## 十一、阻塞代码：最怕演员霸占镜头不走

`asyncio` 最怕一种演员：

> 明明要等很久，却站在主摄像机前不走。

比如：

```python
time.sleep(5)
```

这就像演员站在镜头前说：

> 我现在要等 5 秒，但你们谁也别拍，大家都陪我等。

这会把整个 Event Loop 卡死。

因为 Event Loop 只有一个主摄像机。如果某个演员霸占镜头不让出来，其他任务都没法继续。

所以在 async 代码里，应该用：

```python
await asyncio.sleep(5)
```

它的意思是：

> 我自己去等 5 秒，导演你先拍别人。

这就是同步阻塞和异步等待的区别。

---

## 十二、ThreadPool：真的很慢的活，丢到幕后去做

有些活天生就是阻塞的，比如：

- 读一个很大的文件
- 调一个很慢的同步函数
- 做一段不支持 async 的旧代码
- 执行某些 CPU 或 IO 阻塞操作

这些事情如果直接放在主片场，会卡住 Event Loop。

这时候可以用：

```python
await asyncio.to_thread(blocking_function)
```

这就像导演说：

> 这个活不要占主摄像机，送到幕后工作间去做。做好了再通知我。

幕后工作间就是 **ThreadPool**。

等后台线程干完活，会通过 Future 通知 Event Loop：

> 那个活好了，可以让演员回来继续演了。

然后对应的 Task 再次进入 Ready Queue，等待下一次上场。

---

## 十三、完整片场流程

现在把整个流程串起来：

| 步骤 | 片场画面 | asyncio 里发生了什么 |
| --- | --- | --- |
| 1 | 程序员写剧本 | 写下 `async def` |
| 2 | 剧本被拿出来 | 调用 coroutine，得到 coroutine 对象 |
| 3 | 安排演员 | Event Loop 把 coroutine 包装成 Task |
| 4 | 演员候场 | Task 进入 Ready Queue |
| 5 | 导演叫号 | Event Loop 从 Ready Queue 取出 Task |
| 6 | 演员开始表演 | Task 开始执行 coroutine |
| 7 | 演员遇到等待 | 执行到 `await`，Task 主动暂停 |
| 8 | 镜头切走 | Event Loop 去调度其他 ready 的 Task |
| 9 | 幕后通知 | Future 完成，通知 Task 可以继续 |
| 10 | 演员回到候场区 | Task 回到 Ready Queue |
| 11 | 导演再次叫到他 | Event Loop 再次调度这个 Task |
| 12 | 接着上次演 | Task 从上次暂停的位置继续执行 |

这一套流程不断循环，就是 `asyncio` 的基本运行方式。

---

## 最后再记一遍

如果只记一句话，可以记这个：

> Event Loop 像片场总导演，Ready Queue 像候场区，Task 像拿着剧本的演员，Coroutine 是剧本，await 是演员主动让出镜头，Future 是幕后通知单。

再通俗一点：

> `asyncio` 不是让所有演员同时站在镜头前表演。
>
> 它是让会等待的演员主动退场，让导演趁这段时间去拍别人。
>
> 等演员准备好了，再回到候场区，继续接着刚才的地方演。

这就是 Event Loop 和 Ready Queue 的核心。
