# 时间复杂度（Time Complexity）

**核心定义**：描述算法的执行步骤数，如何随输入规模 `n` 的增长而增长。
> [!NOTE]
> 时间复杂度不关心具体用了多少秒（由于不同机器的 CPU 速度差异极大），它只关心**执行步骤的增长规律与趋势**。

**读法说明**：
* `O(1)`：英文可读作 **order of one**，也叫 **常数时间复杂度**。
* `O(n)`：英文可读作 **order of n**，也叫 **线性时间复杂度**。
* `O(n²)`：英文可读作 **order of n squared**，也叫 **平方级时间复杂度**。

这里的 `O` 是字母 O，不是数字 0；它通常理解为 **Order（阶）**。这套写法叫 **Big O notation**，中文通常叫 **大 O 表示法**，用来描述算法随着数据量变大时的增长趋势。

## 核心概念类比
用“收拾房间”来做个类比。假设**房间面积**就是我们要处理的 **“数据量（n）”**。

### 1. O(1) —— 常数时间复杂度
* **代码示例**：双端队列的弹出 `deque.popleft()`
* **类比【关灯】**：不管是一个 10 平米的小卧室，还是一个 1000 平米的大厂房（数据量激增），只要找到门边的开关按一下，房间就黑了。
* **特征本质**：执行步骤是固定数量，不会随着数据量变大而增加。

### 2. O(n) —— 线性时间复杂度
* **代码示例**：普通列表的头部弹出 `list.pop(0)`
* **类比【扫地】**：10 平米的小房间，你挥扫帚可能要挥 10 次；如果是 100 平米的房间，你就要挥 100 次。
* **特征本质**：房间的面积（数据量 `n`）扩大了多少倍，你的执行步骤大致也会按 **相近比例** 增加。画在图表上就是一条向上增长的直线。

### 3. O(n²) —— 平方级时间复杂度
* **代码示例**：双重循环嵌套
* **类比【乘法口诀表】**：假设口诀表有 10 行、10 列，每个格子都要计算一次，那么总共就是 `10 × 10 = 100` 次计算。如果规模翻倍，变成 20 行、20 列，计算次数就会变成 `20 × 20 = 400` 次！
* **特征本质**：**数据量仅仅翻了一倍，工作量却直接翻了 4 倍。**
* **结论**：这种算法在数据量小的时候看不出弊端，但在处理海量数据时，很容易变得非常慢，甚至卡死机器。

### 4. O(log n) —— 对数级时间复杂度

* **代码示例**：最小堆里的向上冒泡 / 向下下沉

* **类比【淘汰赛】**：假设有 1024 个选手参加单败淘汰赛。第一轮 1024 人变 512 人，第二轮 512 人变 256 人，第三轮 256 人变 128 人……每一轮都会淘汰一半。

所以选出冠军并不需要经历 1024 层，而只需要：

1024 -> 512 -> 256 -> 128 -> 64 -> 32 -> 16 -> 8 -> 4 -> 2 -> 1

在最小堆里也是类似的。堆底层虽然是数组，但逻辑上可以看成一棵完全二叉树。`heappush()` 时，新元素从最后一个位置开始，只需要沿着 parent 一层层往上比较；`heappop()` 时，堆顶被弹出，最后一个元素补到堆顶，也只需要沿着 child 一层层往下比较。（[点击查看：最小堆](minheap.md)）（[点击查看：二叉树](binarytree.md)）

特征本质：数据量即使变大很多，操作次数也只是按“树的高度”慢慢增加。
